Self-host

One command, in your own Cloudflare account

The Postern installer sets everything up in your account with your own API token. It talks only to the Cloudflare API. Your mail, your store and your keys never leave your account.

What you need

  • A Cloudflare account, and a domain on it that uses Cloudflare DNS.
  • To send mail, the Cloudflare Workers Paid plan (USD 5 a month, paid to Cloudflare). Cloudflare Email Sending requires it. Receiving works on the free plan.
  • Node 22 or later, and a clone of the Postern repository.
  • A Cloudflare API token with the permissions listed in deploy/README.md. The installer checks each one and names any that is missing before it changes anything.

Install

git clone --branch v1.14.0 https://github.com/skyphusion-labs/postern && cd postern
export CLOUDFLARE_API_TOKEN=<your token>

node deploy/postern.mjs install --domain your-domain.example --dry-run
node deploy/postern.mjs install --domain your-domain.example

This installs Postern v1.14.0, the current release. The dry run prints the plan and changes nothing. The real run then:

  1. Creates the D1 database and the R2 attachment bucket, and applies the schema.
  2. Deploys the Worker at mail. on your domain, with a mailbox token it generates.
  3. Turns on Email Sending and Email Routing, and adds the DNS records they need.
  4. Adds a DMARC record only if your domain has none. An existing DMARC policy is never changed.
  5. Creates your first admin login and turns on webmail sign-in.

Every line of output names one resource and says created, updated, unchanged or kept. Your credentials go to a local file with mode 600. The installer prints its path, never the values.

What we measured on a fresh domain on 2026-11-10: the install took 22 seconds. Cloudflare accepted the first send about a minute later, and a message sent to the domain was stored 2 seconds after that.

It refuses before it breaks anything

The installer collects every problem first and changes nothing if it finds one. For example, it refuses when your domain already receives mail somewhere else, when an Email Routing rule already sends mail elsewhere, when your SPF record needs a merge by hand, or when the web hostname is already in use.

Run the same command again and it changes nothing. A run that stopped partway resumes where it left off.

Keep it current

To upgrade, check out the newer release tag, then run node deploy/postern.mjs upgrade. It applies only the new migrations, then deploys the new Worker. Before it migrates, it records a D1 Time Travel bookmark and the Worker version it replaces, so rollback can go back. status gives a read-only report at any time.

Upgrade and rollback in DEPLOY.md

There is no hosted Postern

Skyphusion Labs does not run Postern for anyone. There is no account to sign up for, and we hold none of your mail. The only Postern instance we run is the public demo, a shared mailbox with a read-only token.

No Cloudflare account yet? Run the whole mailbox on your computer under wrangler dev first.
