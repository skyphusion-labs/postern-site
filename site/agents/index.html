For agents

A mailbox your agents can use as themselves

Postern was designed for agents from the start. An agent connects over MCP, gets its own identity and a token with only the scopes you grant, and every answer says exactly what it covered.

Connect over MCP

The MCP server is published on npm as @skyphusion/postern-mcp. It is a small stdio server over the Postern mailbox API, so it works with Claude Code, Cursor and other MCP clients.

{
  "mcpServers": {
    "postern": {
      "command": "npx",
      "args": ["-y", "@skyphusion/postern-mcp"],
      "env": {
        "POSTERN_API_URL": "https://mail.your-domain.example",
        "POSTERN_API_TOKEN": "your agent token"
      }
    }
  }
}
  • Read tools, always on: search, list, read a message, read a thread, and list folders. Search defaults to hybrid (semantic plus keyword), with full-text, semantic and literal substring modes too.
  • Send tools, opt-in: mailbox_send, mailbox_reply and the draft tools register only when you also set a send credential. An agent that should only read never sees them.

Point it at the public demo to try the read tools now. The demo URL and its read-only token are in the Postern README.

Full MCP tool reference

Each agent sends as itself

Instead of one shared mailbox password, you register one token per person or agent. Each token is bound to one address and carries its own scopes, such as read, send, or both. The registry stores only token hashes, never the tokens.

So a leaked token is limited to what it was for, and every sent message shows which identity sent it.

How per-identity credentials work

Every read says what it covered

Every read answer includes an identityScope field. It reports the scope the server applied, not the one the caller asked for. An agent never has to guess whether an empty result means "not in the mailbox" or "not in my slice".

The mailbox API contract

What an agent token can read

By default, a read-capable agent token reads every address on its deployment, including the people on it. That is on purpose: an agent asked to find last month's invoice must be able to read the mailbox it was delivered to.

  • An agent can change only its own mail. Marking read, flagging, filing and quoting in a reply stay bound to its own address.
  • To keep an agent send-only, give it a token without the read scope. Every read route refuses it.
  • A person signed in to webmail reads only their own address, plus any shared role address they are on.

The full credential table

A trust signal agents can rely on

Each stored message carries a trusted flag. It is set only when the sender is on your allowed sender domains and the message passes aligned DMARC or DKIM. SPF alone never counts. An agent can act on mail from your own systems and treat everything else with care.
